## 四、Loop／Graph 設計

逐篇讀取與摘要來源 → 更新 Wiki 與來源索引 → 依教學目標查 Wiki → 擬定每頁主張與來源 → 審核大綱 → 逐頁生成與檢查 → 整合 HTML → 測試導覽、練習題與連結。

- 來源階段逐篇執行讀取、摘要、登錄。若來源無法讀取，先尋找可讀版本或替代教材，再更新 Wiki。
- 大綱階段核對每頁的規則、例句和對應條目。規則涵蓋的範圍有疑問時，回查原教材並重審該頁；若 Wiki 本身有缺漏，先更新 Wiki。
- 逐頁檢查題幹、選項與解析是否一致。檢查失敗就只修正該頁，再測受影響的連結與互動。每頁通過後即可進入整合測試，若同一頁重試兩次仍無法確認，就人工查證。
- 先查大綱再生成 HTML，可以在改動成本較低時發現規則錯誤。把內容檢查和互動檢查放在相應步驟，也能較快定位該修哪裡。

## 六、反思

這次實跑中，教學規則的範圍最容易出錯。原本的大綱用「降る」當代表例，卻把單一例子的型態寫成整個規則。一次實跑只能指出這次觀察到的問題，沒有足夠次數比較長期錯誤率。我把「用不同時態的來源例句檢查接續規則」提前到大綱審核，並在生成頁面前回查 W02／S05。這樣既保留初學者容易理解的「降る」，也避免漏教「閉まった」這類普通形過去式。
